## Что не потерять при переносе ТЗ

Типовое ТЗ состоит из десяти разделов. Отметь, что нашёл, чтобы ничего не выпало:

- [ ] Общие сведения: название, формат решения, тип задачи
- [ ] Описание проблемы
- [ ] Пользователь и сценарий
- [ ] Задача хакатона
- [ ] Описание кейса: проблема, задача списком, данные
- [ ] **Минимальные функциональные требования** → в `REQUIREMENTS.md` как REQ-*
- [ ] **Данные и проверочный пример** → в `REQUIREMENTS.md` и в автотест
- [ ] Ограничения и дополнительные возможности → там же оговорка про баллы за бонусы
- [ ] **Метрики и критерии оценивания** → шкала кейса в `REQUIREMENTS.md`
- [ ] Сдача и выполнимость
