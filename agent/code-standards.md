# Стандарты кода

## Честность реализации

Честность реализации проверяется техническими экспертами напрямую (п. 5.4.7: проверка кода, истории и достоверности заявленных результатов) и почти всегда входит в критерии ТЗ.

- **Никаких заглушек, имитаций и захардкоженных результатов в ключевых функциях.** Если внешняя зависимость недоступна — нет ключа, таймаут, ошибка — функция честно сообщает об этом, а не возвращает заготовленный ответ.
- **Режим-заглушка никогда не включается по умолчанию.** Флаг вида `USE_MOCK = true` в коде или в `.env.example` читается как подмена ключевой функции.
- **Если демо-режим нужен — объявить громко:** отдельным разделом в README и видимой пометкой в самом интерфейсе. Честно названная заглушка читается как добросовестность, спрятанная — как обман.
- **Вердикты вычисляются, а не печатаются.** Любая фраза вроде «проверка пройдена» или «расчёт точен» выводится только как результат реальной проверки. Безусловный вывод такого текста — ровно то, что критерий называет заранее подготовленным ответом.

## Структура

- Бизнес-логика отделена от интерфейса. Расчёты — в чистых функциях, покрытых тестами: ядро должно проверяться без браузера.
- Без избыточной архитектуры. Простое законченное лучше сложного недоделанного.
- Говорящие имена файлов, функций и тестов: по имени понятно, какое требование закрывает код.
- Минимум зависимостей, каждая новая обоснована. Lock-файл коммитится.

## Ввод и ошибки

- Валидация всего пользовательского ввода: пустые значения, неверные типы, нули и отрицательные числа, неверные даты, слишком длинные строки. Ошибки — понятным текстом, без стектрейсов.
- **Валидируется значение, а не только тип.** Строка правильного типа может содержать `%`, пустоту или служебный символ и уехать прямо в запрос.
- Пустые состояния и повреждённые сохранённые данные не ломают приложение.
- Ошибки внешних API перехватываются.
- Сбой видно на экране, а не только в консоли.

## Безопасность

- Параметризованные запросы к базе, экранирование вывода.
- Секреты только в переменных окружения и только на сервере. **Ключ провайдера никогда не попадает в переменную фронтенда** — он окажется в собранном бандле дословно.
- Если в продукте есть данные разных пользователей — нужна хоть какая-то идентификация. Идентификатор пользователя параметром запроса со значением по умолчанию — это отсутствие разграничения доступа.
